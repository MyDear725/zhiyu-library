# 知遇 LibraryOS 企业级升级设计

## 目标

将既有的馆藏发现、场景选座、学习意图、同伴广场和馆内问答编排为一个可解释的 LibraryOS：用户表达学习目标后，系统给出知识、空间与同伴三类行动；真实行为沉淀为仅本人可见的知识孪生，并以匿名聚合形式支持运营洞察。

## 范围

- 新增统一行为事件层、行动型 AI 馆员、个人知识孪生、低曝光馆藏推荐和匿名运营洞察。
- 为未来学习气候数据与匿名问题墙定义 Space Engine、People Engine 的输入/输出契约。
- 首页新增 AI 馆员入口；“我的”页新增知识孪生；新增演示运营视图。
- 不重写现有借书、选座、社区页面；不实现真实 IoT、室内定位、向量数据库或复杂知识图谱。

## 架构

`lib/libraryos` 保存共享类型、真实演示馆藏、事件写入、空间/同伴引擎、知识孪生和计划生成逻辑。`app/api/libraryos` 只做认证、输入校验和 JSON 响应；任何模型调用只能提供对目标的解释，实体事实始终由本地目录和数据库决定。

`activity_events` 是唯一新增持久化表。写事件为 best-effort：主业务成功后尝试写入，写入失败只记录服务端警告。事件 metadata 只存归一化主题、书籍编号、目的和时段等非敏感字段；不存密码、token、学号或原始私人问题。

## 用户流程

1. 登录用户在首页输入 2–500 字目标。
2. AI 馆员从共享馆藏目录、当前座位、学习意图和匿名聚合中生成固定格式计划；无 API Key 时使用同一格式的本地规则。
3. 卡片可进入借书、选座或同伴广场；生成计划和后续行为均写入事件层。
4. “我的”页读取本人借阅与事件，显示真实主题、书籍和关联边；无数据时显示引导空状态。
5. 演示运营视图只读取匿名聚合 KPI 和排行，不返回任意用户身份或原始内容。

## 数据与隐私约束

- 推荐书名、可借量、位置、楼层、座位状态只能来自共享演示数据或数据库。
- 低曝光推荐显示为“低曝光探索推荐”，不伪造历史借阅量。
- Knowledge Twin 仅以当前认证用户为查询范围；运营 API 不返回 user_id、姓名、学号或原文。
- OpenAI 不可用、响应错误或无法解析时，接口返回本地计划，不将错误暴露为系统事实。

## 验收

- `/api/libraryos/librarian/plan` 对有效目标返回知识、空间、同伴行动和真实书籍；无密钥仍可用。
- 搜索、加入借阅、保存学习意图及创建计划均尝试写入安全事件。
- 知识孪生与运营洞察有真实数据和无数据两种正确状态。
- 保持现有登录、借阅、预约、社区接口；通过测试、构建及 lint。
